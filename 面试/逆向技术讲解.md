# 《再续天庭》EXE、Enigma 与 SWF 资源逆向技术讲解

> 状态基线：2026-08-24。资源恢复已完成；当前工作不是继续验证“素材是否存在”，而是按具体资源族建立可消费的原版真值。

## 30 秒结论

原始游戏把角色、怪物、关卡和 UI 的 SWF 放进 Enigma Virtual Box 虚拟文件系统，并对多数 SWF 的前 176 bytes 做了重排。仅扫描 `FWS/CWS/ZWS` 文件头会得到缺少原始路径的数字候选，容易误判素材缺失。

我从 AS3 加载链确认资源路径和字节变换，再恢复 EXE 的虚拟文件系统。最终得到 206 个原始命名文件；175 个 SWF 中 174 个被还原为 FFDec 可解析的标准 SWF。此后资源工作改为“定位源包和 Symbol → 解析时间轴与几何 → 生成机器真值 → 现代实现直接消费”，而不是人工猜图。

## 1. 真正的难点是什么

这不是一个“会不会使用反编译器”的问题，而是三层封装叠加：

1. **容器层**：资源没有以普通目录存在，而是位于 EXE 的 Enigma 虚拟文件系统。
2. **格式层**：多数解包后的 `.swf` 仍不是标准文件头，需要按原 AS3 加载逻辑重排字节。
3. **语义层**：FFDec 能打开文件只说明结构可解析，不说明哪个 Symbol、哪一帧、哪个 child 才是运行时真正显示的对象。

因此，任何单点工具都不足以完成恢复。需要把 PE/容器证据、AS3 调用链、SWF 时间轴、运行时状态和现代消费连起来。

## 3. 为什么早期只得到数字 SWF

早期方案直接在 EXE 字节中扫描标准 SWF 头。这种方法只能命中碰巧仍保留 `FWS/CWS/ZWS` 特征的片段：

- 绕过了 Enigma 的文件目录，因此丢失 `assets/WuKong.swf`、`assets/levels/level11.swf` 等原始路径；
- 可能从大文件内部截出重叠或嵌套片段；
- 无法处理被前 176 bytes 重排的包；
- 文件能被部分解析，也不等于标签、时间轴和帧语义完整。

数字候选仍可作为历史对照，但不能再作为“原版视觉是否存在”的最终依据。

## 4. 176-byte 重排是怎样被证明的

AS3 加载器先读取资源包，再执行等价于以下变换的逻辑：

```text
input[97..175] + input[0..96] + input[176..end]
```

它把原文件的第 97—175 字节移到开头，再接第 0—96 字节和剩余内容。对恢复文件执行同样变换后，多数包重新出现合法 `FWS/CWS/ZWS` 签名，声明长度和解压后长度一致，FFDec 能解析到完整标签流和唯一 End 标签。

这里的关键不是“猜到一种加密算法”，而是从游戏自己的加载代码恢复确定性变换，再用全量结果和代表样本验证。

## 5. 现在寻找一个 UI 或动画的完整路径

当前标准链路是：

```text
AS3 调用点 / SymbolClass / Aloader 补丁顺序
  → restored-swfs 中定位原始命名源包
  → FFDec 导出目标 Symbol 的 XML、shape、sprite、SVG 或逐帧 PNG
  → 解析 child、depth、frame、matrix、registration、bounds、mask/filter
  → 生成带来源哈希和 Schema 的 verified 机器真值 JSON
  → 现代 manifest / atlas / runtime 直接消费
  → 确定性测试 + 原版基准 + 940×590 逐状态验收
```

每一层回答不同问题：

- AS3 说明对象在什么状态下被创建、切帧、移除或替换。
- SymbolClass 和加载顺序说明同名类最终由哪个包提供。
- SWF XML/时间轴说明显示对象的真实结构与几何。
- SVG/PNG 基准说明视觉输出是否与解析结果一致。
- 现代运行验收说明真值是否真的被消费，而不是只存在于文档中。

## 6. 一个最能说明问题的近期反例

宠物战斗 HUD 的旧真值已经通过 Schema、资源和运行测试，但正式画面仍错误。根因是旧生成器只记录 character 657 根容器的 42 帧联合 bounds，现代实现又用宠物身体 atlas 代替头像。实现、测试和真值围绕同一个错误前提自洽。

新的处理方式是：

1. 从宠物语料和 AS3 中文名映射独立声明 35 个应出现的头像状态。
2. 对每个目标帧递归 child，找到真正的终端 shape，而不是使用根容器联合边界。
3. 生成 35 个逐帧原版 baseline、70 个 P1/P2 投影和 4 个无出战/休息负状态。
4. 对 child、frame、matrix、registration 和 visible bounds 做变异测试，确保改错任何关键字段都会导致验证失败。
5. 现代 HUD 直接导入新 manifest，删除身体 atlas、联合 bounds 拉伸和硬编码头像定位。
6. 用九物种资源像素差、五关 P1/P2 旅程和 940×590 零 console 证明正式消费闭环。

这个案例说明：**恢复文件只是起点，真正困难的是构造不与实现共享错误前提的事实链。**

## 7. 工具各自负责什么

| 工具或方法 | 职责 | 不能证明什么 |
| --- | --- | --- |
| EVB 解包 | 恢复虚拟文件系统和原始路径 | 文件内部语义正确 |
| AS3 调用链 | 解释加载、状态和动态显示行为 | 每个像素和几何值都正确 |
| 176-byte 还原 | 恢复标准 SWF 结构 | 目标 Symbol 就是当前业务对象 |
| FFDec | 解析 Symbol、时间轴、shape、sprite 和脚本 | 现代运行时已经正确使用这些对象 |
| 真值生成器 | 固化来源、状态、显示列表和几何 | expected 范围天然完整 |
| 自动测试 | 验证声明的结构与行为 | 用户看到的画面和手感必然正确 |
| 940×590 运行验收 | 验证正式组合路径和可见结果 | 所有未覆盖状态都已正确 |

所以验证必须组合使用，不能把某个工具的成功退出码外推成整个复现完成。

## 8. 资源接入边界

- 不修改、删除或重新生成 `local-resources/regima/legacy-extraction/` 的原始结果。
- 视觉资源优先从 `source/restored-swfs/` 窄查，旧提取结果只做交叉对照。
- 不把 174 个 SWF 一次性全部导入 `public/assets`；只按当前任务选择性派生。
- 每个派生产物保留源包、Symbol、帧、哈希和生成方式，避免素材脱离 provenance。
- `missing-original` 只表示检索恢复语料后仍确认缺少源文件，不能表示“尚未导出”。具体规则见 [资源标注 Schema](../docs/reverse-engineering/asset-annotation/annotation-schema.md)。
- 唯一未解析的 `assets/231111.swf` 保持 unresolved，除非后续证据证明其格式或用途。

## 9. 面试可直接使用的回答

### 30 秒版本

> 原游戏的真资源并没有直接放在目录里，而是被 Enigma Virtual Box 封进 EXE，多数 SWF 还做了 176-byte 头部重排。直接扫 SWF 文件头只能得到无名称的残片。我先从 AS3 加载链确认资源路径和字节变换，再恢复虚拟文件系统，最终得到 206 个原始命名文件，175 个 SWF 中 174 个可解析。之后我没有批量导图，而是按业务状态定位 Symbol、解析时间轴和嵌套矩阵、生成带来源哈希的机器真值，再让 Phaser 运行时直接消费并做逐状态验收。

### 被追问“为什么 FFDec 打开了还不算完成”

> FFDec 只能证明 SWF 结构可解析。一个 UI 的真实状态还可能由 AS3 动态 `gotoAndStop`、嵌套 child、加载补丁顺序和运行时文字决定。宠物 HUD 就出现过“真值和测试都通过但画面仍错”的反例，因为提取单位选成了根容器联合边界。后来我把 expected 状态、SWF actual 提取和现代消费拆开验证，才避免同源自证。

### 一句话收束

AS3 是资源的使用说明，Enigma 是封装资源的集装箱，FFDec 是拆箱工具；机器真值和运行验收负责证明拿出的对象、状态与现代投影确实是对的。
