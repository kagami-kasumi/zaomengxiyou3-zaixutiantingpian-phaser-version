# 本项目最有挑战性的事情是什么？是如何解决的？

## 核心答案

本项目最有挑战性的事情，不是把 AS3 改写成 TypeScript，而是：

> **从不完整、分散、甚至会互相误导的遗留资料中恢复“原版到底怎样运行和显示”的可靠事实，并证明现代实现真的消费了这些事实。**

原始行为分散在局部 AS3、共享运行时、MovieClip 时间轴和动态加载逻辑里；视觉对象又受到 SymbolClass、嵌套 child、帧、矩阵、注册点和加载补丁顺序影响。更棘手的是，实现、真值生成器和测试可能共享同一个错误理解，于是所有检查都通过，玩家看到的结果仍然不对。

我最终把这个问题从“凭经验复刻”改造成一条可追溯、可反证的证据链。

## 为什么它最难

### 1. 源码可读，但不是完整事实

反编译 AS3 往往只展示局部行为。一个关卡的输入、物理、镜头、刷怪、死亡、结算和存档可能分别由不同共享对象负责。直接翻译某个类，容易得到局部自洽但整体错误的实现。

### 2. 资源存在，不等于知道运行时显示哪个对象

项目从 EXE 恢复出 206 个原始命名文件，175 个 SWF 中 174 个可解析。但 FFDec 能打开 SWF，只能证明结构存在；运行时可能通过 `gotoAndStop`、动态 `addChild`、同名类补丁和嵌套时间轴选择另一个 child 或帧。

### 3. 测试通过也可能是自证

如果 expected、实现和测试都由同一个错误假设生成，它们会一起通过。早期宠物 HUD 就把 42 帧联合 bounds 和宠物身体 atlas 当作头像事实，Schema、资源检查和运行测试都没有发现语义错误。

### 4. 现代化不能照搬 Flash 架构

即使原版事实已经恢复，也不能把全局对象、显示对象副作用和时间轴状态直接翻译成现代代码。还需要区分“必须还原的可观察行为”和“可以重新设计的内部结构”。

## 我是如何解决的

### 第一步：恢复权威源语料

从 AS3 加载链确认 Enigma 虚拟文件系统和前 176 bytes 重排逻辑，恢复原始命名资源，并用哈希、文件数、SWF 声明长度、标签流和代表样本做可复现验证。视觉检索从此优先使用 `local-resources/regima/source/restored-swfs/`，旧数字 SWF 只作历史对照。

### 第二步：建立六段证据链

```text
局部 AS3 / 时间轴
  → 共享运行时调用链
  → SWF 几何与坐标语义
  → 与架构无关的可观察行为合同
  → 现代 owner 映射
  → 确定性测试 + 正式运行观察
```

结论明确分为确认、交叉确认、推断、未知和现代设计选择。证据缺环时保留未知，不把方便实现的常量包装成原版事实。

### 第三步：把视觉事实做成机器可消费的真值

对 UI、HUD、角色和动画记录：

- source SWF、SHA-256、SymbolClass 和加载 owner；
- child、depth、frame、matrix、registration 和 visible bounds；
- normal、hover、pressed、selected、负状态和动态文字来源；
- 原版逐状态 SVG/PNG baseline；
- 允许的现代视觉例外和 unresolved 项。

现代 manifest、atlas 和 runtime 直接导入这些 JSON，避免文档写一套、代码再手抄一套。

### 第四步：拆开 expected、actual 和消费验证

expected 尽量从独立的业务声明得到，例如 AS3 状态映射、角色/宠物目录和用户可观察路径；actual 从 SWF XML、时间轴、SVG/PNG 中提取。随后用变异测试验证关键字段真的影响结果，再用正式运行证明现代代码确实消费真值。

这一步专门防止“生成器把自己写入 JSON 的常量再读回来验证”的同源自证。

### 第五步：用现代 owner 重建，而不是逐类翻译

现代实现按 Scene、纯 System、Registry、Bridge 和只读投影分层：

- 关卡负责遭遇编排，不负责怪物内部规则；
- 运行时 Registry 持有稳定实体 ID 和可变状态；
- 战斗、物理、奖励、存档和 UI 各有唯一 owner；
- P1/P2 owner 从输入贯穿库存、装备、技能、宠物、事务和 V6 存档；
- Phaser 视图消费状态，不成为业务事实来源。

最后同时运行专项测试、全系统回归、TypeScript 构建和 940×590 正式浏览器验收。

## 最有说服力的具体案例：宠物 HUD 头像纠错

这是一个很适合面试展开的案例，因为它证明问题不只是“缺资源”，还包括验证体系本身可能失效。

**问题：** 旧真值把 character 657 的联合边界和宠物身体图当成 HUD 头像。形式校验全部通过，但正式画面错误。

**定位：** 从 35 个宠物形态声明和 AS3 中文名映射独立建立 expected；再对每个目标帧递归 SWF child，发现灵猴实际是 frame 5、character 619、约 `46.75 × 40`，而不是旧的约 `104.8 × 93.6` 联合画布。

**修复：** 生成 35 个 fixture、70 个 P1/P2 投影、4 个负状态和逐帧 baseline；现代 HUD 直接消费 33 个唯一终端 child，删除身体 atlas、联合 bounds 拉伸和硬编码头像定位。

**验证：** child/frame/matrix/registration/visible-bounds 变异门禁通过；九物种运行资源与 baseline 像素差为 0；五关 P1/P2 旅程、全系统、构建和 940×590 运行零 console 通过。

**沉淀：** 这次反例没有只修一个头像，而是推动视觉真值流程增加独立 expected、递归动态 child、逐 fixture baseline、变异测试和正式消费者验证。

## 第二个验证反例：猴系虚空攻击

这个案例适合回答“测试都是 AI 写的，如何避免既当裁判又当运动员”。

**问题：** 猴系动画和攻击特效已经接入，专项、系统设计 P1R 和正式运行观察都曾通过，但玩家发现宠物会在怪物很远时原地放招，不追击也打不中。

**定位：** 原版 `BasePet` 与 207 行为合同已经包含每个形态的 `attackRange` 和范围外追击事实；缺失不在逆向证据，而在验证结构。现代测试只确认 41 个合同 id 被读取，并把敌人直接放到 projectile 坐标；运行观察只看到“特效出现、怪物 HP 下降”，没有证明两者属于同一只宠物、同一次攻击和同一条时序链。

**机制：** 将标准答案与运行结果分源：expected 在实现前由原版 AS3/SWF 和 manifest 冻结，actual 从黑盒运行 trace 采集。每个关键字段必须映射到场景和断言；增加“目标在攻击范围外时不得创建攻击、必须追击”的负场景；trace 记录双方位置、距离、动作、projectile、attack id、damage source 和 HP 前后值。再故意变异攻击距离或 owner，确认 verifier 会失败。

**价值：** 另找一个 AI 写测试只能降低部分遗漏概率，不能天然提供独立真值。真正的独立性来自 expected、实现和 actual 的数据流隔离，以及错误字段能被 mutation-kill。这个反例让“测试通过”从一个布尔结果，升级为可解释、可证伪的运行证据链。

## 30 秒面试回答

> 这个项目最有挑战性的不是把 AS3 翻译成 TypeScript，而是从不完整的反编译代码、共享运行时和嵌套 SWF 时间轴里恢复可信的原版事实。单个工具和单组测试都可能给出自洽但错误的答案。我先恢复了 EXE 中的原始命名 SWF，再建立“局部代码、共享调用链、SWF 几何、行为合同、现代 owner、测试与运行观察”的六段证据链。视觉部分生成带源哈希的逐状态机器真值，让现代代码直接消费，并用变异测试和 940×590 正式运行反证。这样解决的不是一次性的资源缺失，而是让后续关卡、UI 和动画都能用同一套可复查方法恢复。

如果岗位更偏 AI Engineering / Harness Engineering，可把最后两句替换为：

> 后来我又遇到宠物在攻击距离外虚空放招，但 AI 生成的专项和门禁仍全部通过。这个反例让我把验证拆成独立 expected、合同字段级断言、负场景和黑盒运行 trace，并用 mutation-kill 检验字段是否真的被覆盖。核心不是换一个 AI 当 reviewer，而是让标准答案、实现和运行结果的数据流彼此独立。

## 90 秒 STAR 回答

> **Situation：** 我在用 Phaser 3 和 TypeScript 重写一款 Flash 双人动作 RPG。资料约 20 万行反编译 AS3，资源被封在 EXE 中，行为又分散在时间轴、共享对象和动态加载链里。早期甚至出现过真值、实现和测试全部通过，但正式宠物 HUD 头像仍错误的情况。
>
> **Task：** 我的任务不是让页面“看起来差不多”，而是建立一种能持续回答“原版事实是什么、现代代码是否真的还原”的方法，同时避免照搬 Flash 的全局状态和显示对象耦合。
>
> **Action：** 我先从加载代码恢复 Enigma 虚拟文件系统和 176-byte SWF 重排，得到 206 个原始命名文件，175 个 SWF 中 174 个可解析。然后建立六段证据链，把确认事实、推断、未知和现代设计分开。UI 和动画进一步生成带 Symbol、frame、child、matrix、bounds 与原版 baseline 的 verified JSON，现代 runtime 直接消费。针对宠物 HUD，我又把 expected 状态、SWF actual 提取和消费验证拆开，并加入关键字段变异测试。
>
> **Result：** 五个正式关卡、双玩家 V6 存档和主循环已经闭合；宠物 HUD 的 35 个头像状态纠错后，九物种资源像素差为 0，五关 P1/P2 与 940×590 运行通过。更重要的是，这套流程把一次排错沉淀成了后续 UI、角色和宠物动画都能复用的恢复方法。

## 回答时不要过度声称

- 174 个 SWF 可解析，不等于全部视觉已接入。
- 自动测试通过，不等于手感、镜头和所有视觉状态都正确。
- 当前猴系和马系宠物真动画资源已接入，但猴系行为 P1R 已因攻击距离/追击反例降级，行为 verifier 与整改仍在进行；其余七族、五角色动作统一校准和战斗技能 HUD 也未完成。
- 现代实现追求可观察行为、数值、手感和流程接近原版，不追求逐行复刻 AS3。
