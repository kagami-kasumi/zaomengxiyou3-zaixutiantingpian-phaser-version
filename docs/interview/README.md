# 项目讲解与面试材料

本目录集中存放可以直接用于面试、答辩或向他人介绍本项目的讲述材料。任务台账、逆向证据和架构合同仍保留在各自的权威目录；这里负责组织讲法，不复制项目状态。

## 推荐阅读顺序

| 材料 | 适合讲什么 | 建议用法 |
| --- | --- | --- |
| [面试.md](面试.md) | Harness Engineering、长期 Agent 协作、工程治理、MCP/LSP | 非游戏岗位主稿；准备 30 秒、2 分钟和深挖三档表达 |
| [游戏-面试.md](游戏-面试.md) | Flash 游戏现代化、双玩家、战斗/存档/事务、原生 UI | 游戏或前端图形方向主稿 |
| [设计模式.md](设计模式.md) | 怪物与关卡架构、组合优于深继承、SOLID 和传统模式映射 | 架构追问或白板题 |
| [逆向技术讲解.md](逆向技术讲解.md) | EXE/Enigma/SWF 恢复、资源取证与最小风险实验 | 逆向、遗留系统迁移或复杂排障追问 |

## 一套完整讲法

1. 先用 `面试.md` 或 `游戏-面试.md` 的 30 秒概述说明项目价值和本人职责。
2. 根据岗位选择一个代表案例：Agent Harness、双玩家数据所有权、原子事务、UI 原生化或关卡/怪物架构。
3. 用 `设计模式.md` 解释现代代码为什么这样拆，而不是只说“做了重构”。
4. 用 `逆向技术讲解.md` 说明结论如何从不完整资料中被证明。
5. 回到主稿的“不应过度声称”与常见追问，主动区分已确认事实、工程集成和仍在演进的部分。

## 权威支撑材料

需要核对最新状态或展示证据时，回到以下原始资料：

- 项目路线与执行状态：`TASK_OUTLINE.md`、`docs/tasks/feature-lines.md`、`docs/tasks/task-board.md`。
- Agent 工作流与治理：`AGENTS.md`、`docs/workflow/agent-protocol.md`、`docs/workflow/problem-governance.md`。
- 现代代码边界：`docs/architecture/src-boundaries.md`。
- 逆向证据与资源标注：`docs/reverse-engineering/`。

面试材料是讲述入口，不替代这些权威来源；涉及数字和完成状态时，应以当前台账、代码和验证结果为准。
