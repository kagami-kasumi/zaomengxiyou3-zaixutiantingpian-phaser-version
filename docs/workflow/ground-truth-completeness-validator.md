# 真值产物全面性校验器讨论稿

状态：待后续独立对话讨论。

关联问题：`PG-017 真值表不管用`。

本文只保存已经由用户冻结的职责边界和下一次讨论必须回答的问题，不提前选择校验算法、不修改 Schema，也不代表校验器已经进入实施。

## 1. 已冻结的前提

- 真值生成逻辑负责完成声明范围内应有的 SWF/AS3 状态解析、目标帧/时间片选择、递归 child 提取、动态显示变化、几何计算和产物生成。
- 生成逻辑漏做应有提取操作属于生成逻辑缺陷，不再额外建立一个校验器监督它是否逐步执行内部流程。
- 校验器只校验生成器最终生成的东西是否全面，不检查内部函数是否被调用、步骤是否按顺序执行或代码覆盖率是否达到某个数值。
- 当前不使用 `correct/incorrect` 作为校验器的独立结果维度。若产物在声明范围内被证明全面，项目即把全面性证明作为真值成立的结论。
- 校验器不得用小于产物声明状态、对象或时间范围的抽样检查宣称“全面”。如何证明其判断范围没有缩小，是下一次讨论的首要问题。

## 2. 生成逻辑与校验器边界

| 事项 | 生成逻辑 | 全面性校验器 |
| --- | --- | --- |
| 冻结原版版本、入口、状态和 fixture | 负责 | 不监督过程 |
| 解析 `gotoAndStop/gotoAndPlay` 与动态显示调用 | 负责 | 不监督过程 |
| 选择目标帧/时间片并递归提取显示列表 | 负责 | 不监督过程 |
| 计算矩阵、注册点和可见 bounds | 负责 | 不监督过程 |
| 生成 manifest 和 baseline 引用 | 负责 | 不监督过程 |
| 判断最终产物是否覆盖声明范围内全部应有内容 | 提供待校验产物 | 负责 |
| 输出单独的 `correct/incorrect` 结论 | 不适用 | 当前不设置 |

生成逻辑的详细拆解以当前 `视觉真值逆向` task 显式链接的 `docs/reverse-engineering/plans/ground-truth-fine-grained-generation.md` 为准。代码逆向不读取该方案或本文；本文不得复制第二份生成步骤并将其变成流程监督清单，也不得要求任何逆向任务通过读取 PG 恢复执行步骤。

## 3. 下一次对话必须解决的问题

1. 校验器依据什么事实集合证明“全面”，而不是只比较生成器自报的 expected/extracted 集合？
2. 如何保证校验范围与产物声明的状态、对象、嵌套层级和时间范围相同，避免校验器比生成器覆盖更少？
3. “全面”的正式定义如何同时覆盖静态帧、`gotoAndStop` 状态、`gotoAndPlay` 时间序列、动态 `addChild/removeChild`、文本、mask/filter 和外部数据？
4. 校验器需要读取哪些输入：规范化产物、恢复 SWF、AS3 状态入口、状态 fixture、基准图或其他来源？这些输入之间如何划分权威关系？
5. 校验结论使用哪些枚举，如何与现有 `verified`、`displayListMatched`、`stateSetMatched` 和 `unresolved` 衔接？
6. 当全面性无法证明时，如何阻止产物进入 `verified`，同时保留可定位的缺口？
7. 如何设计专项和变异测试，证明缺状态、缺 child、缺帧、缺时间语义或复用错误 baseline 时不会得到“全面”结论？

## 4. 本轮明确不做

- 不研发校验器代码。
- 不确定校验算法、第二解析器、运行器或渲染器方案。
- 不修改真值 Schema、现有 manifest 或 `verified` 状态。
- 不批量审计或降级存量真值。
- 不把校验器扩展成生成流程监督器。

只有用户在独立对话中明确讨论或实施全面性校验器，或正式治理项明确链接本文时，才读取本文并继续冻结方案。
