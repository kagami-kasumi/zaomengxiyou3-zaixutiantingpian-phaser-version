# 方法观测协议

本文用于跟踪人或 AI 提出的可重复改进方法，验证它是否真的降低成本、提高质量或减少返工。方法记录使用稳定 `MO-*` id，独立存放在 `docs/workflow/methods/`；本文件只维护通用协议、活跃索引、归档索引和模板。

## 与问题治理的边界

- `PG-*` 从已经存在的系统性缺口出发，目标是清理存量问题并防止复发。
- `MO-*` 从尚待验证的改进假设出发，目标是比较基线与试验样本后决定采纳、修订或停止。
- 同一主题可以先有 `MO-*`、后因证据确认结构性缺口而登记 `PG-*`；转换时保留原方法记录和交叉链接，不能把试验假设改写成既成问题。
- `MO-*` 可以执行和复用 `PG-*` 的校验，集中记录跨任务证据，并在证据满足关闭合同时触发 PG 归档评估。同一份证据可以同时成为 MO 方法样本和 PG 关闭样本，不要求复制两份日志。
- “方法已证明有效”和“问题已满足关闭合同”必须分别裁决：前者不能自动替代后者，但 PG 可以直接引用 MO 或集中审计中的可定位证据。
- 已有明确根因、存量损害和治理义务的事项不得用 `MO-*` 规避问题治理。

## 适用门槛

同时满足以下条件才登记方法观测：

1. 方法会在多个任务、评审、逆向或协作场景中重复使用，而不是一次性偏好。
2. 有可描述的当前基线、预期改善和可能副作用。
3. 能在正常工作中取得可复查样本，不要求为了观测制造无价值工作。
4. 有明确裁决条件和最迟复核点，不会无限保持“观察中”。

不登记：措辞偏好、单次命令选择、局部小修和无法定义对照的主观感受。已经属于 `PG-*` 关闭合同的效果样本，只有在同时提供方法指标或验证可复用治理方法时才计入 MO；否则只作为 PG 证据。

## 记录结构

每个 `MO-*` 独立文档必须包含：

1. **方法与假设**：做法、适用场景、预期因果关系和明确不解决的事项。
2. **基线与指标**：变更前做法、质量/效率指标、护栏指标及取得方式。
3. **试验设计**：样本类型、最少样本量、执行边界、对照方式和停止条件。
4. **采纳标准**：采纳、修订、停止三种裁决的可执行条件。
5. **观测记录**：每次真实适用样本、证据、结果、副作用和后续动作。
6. **裁决与沉淀**：最终结论、适用范围，以及需要写入协议、模板、门禁或 skill 的稳定部分。

记录开头必须写明稳定 id、状态、提出者/来源、负责人和最迟复核点。

## 状态机

- `候选`：假设已记录，尚未满足试验准备条件。
- `试验中`：方法已进入真实工作，正在取得样本。
- `待裁决`：已达到样本量或停止条件，必须作出采纳、修订或停止决定。
- `修订中`：原假设或执行方式需要改版；保留旧版本和失败证据。
- `已采纳待归档`：方法已证明有效，正在把稳定部分沉淀到协议、模板或门禁。
- `已停止待归档`：收益不足、成本过高或副作用不可接受，不再继续试验。
- `已归档`：裁决和沉淀完成，从常规观测集合移除。

达到最少样本量、最迟复核点或停止条件中的任一项，状态必须转为 `待裁决` 或 `修订中`，不得继续无期限收集样本。

## 执行与采样规则

1. `MO-*` 不进入 `task-board.md`，也不因处于活跃状态而抢占 `execution-queue.md`。
2. 试验只能附着在本来就需要执行的正式 task、评审、问题治理或脚手架维护上；如果落地方法本身需要独立跨范围工作，先取得用户授权并按相应流程调度。
3. 执行者只检查当前工作明确声明的 `MO-*` 或其精确触发条件，不扫描全部方法记录，也不为无关变更写“不适用”样本。治理方法可以在试验设计中声明扫描“活跃 PG 索引”；这不是扫描全部 MO，也不允许遍历 PG 归档索引。
4. 样本必须包含可定位证据；时间节省可记录墙钟时间或可复查代理时间线，无法可靠计时时使用重复读取数、冲突数、返工次数、遗漏数、compact 次数等替代指标。
5. 单个成功样本只能证明方法可行，不能自动证明方法普遍有效；达到记录内的样本类型和数量后才允许采纳。但同一份证据若已满足某个 PG 的全部剩余关闭条件，可以直接作为该 PG 的关闭样本并触发归档。
6. 方法引发证据误判、写入冲突、范围扩张或质量门禁退化时，必须记录副作用并按停止条件裁决。
7. 主 agent 或当前工作负责人负责合并样本和作出阶段判断；subagent 不能自行宣布方法已采纳。
