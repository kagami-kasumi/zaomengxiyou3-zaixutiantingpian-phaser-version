# PG-010 灵魂货币所有权错误

状态：已关闭。

来源：2026-07-24 用户指出 `player*.skillLearning.soulCount` 把跨系统通用货币错误挂在技能学习子系统下；炼丹炉、法宝和后续功能同样可以消费灵魂。

## 1. 问题定义

当前灵魂数保存在 `HeroSkillLearningState.soulCount`。这会把玩家通用货币错误建模成技能学习内部状态，并迫使技能页、炼丹炉、法宝等消费者跨越技能边界读写同一数值。

这不是字段改名的小修，而是玩家领域所有权、消费事务、双玩家隔离和存档版本迁移共同存在的数据源问题：

- 灵魂的生命周期属于玩家，不属于任一消费功能。
- P1/P2 必须各自拥有独立的 `player.soulCount`。
- 技能、炼丹炉、法宝和其他功能只能消费当前玩家的同一字段。
- 旧 V1..V5 存档中的嵌套灵魂必须无损迁移，不能重置或复制成双数据源。

## 2. 证据

- `src/systems/SkillUISystem.ts` 的 `HeroSkillLearningState` 直接声明并扣减 `soulCount`。
- `src/systems/SaveSystem.ts` 将灵魂序列化到 `player*.skillLearning.soulCount`。
- 技能、炼丹炉和法宝的正式页面/运行桥接均读取或回写该嵌套字段。
- 多组保存、技能、工坊、法宝和正式旅程测试把嵌套路径固化为当前合同。
- 用户明确确认灵魂还会被更多功能消费，因此技能子系统不能继续充当货币 owner。

## 3. 解决方案

由 `TASK-ARCH-013A` 与 `TASK-ARCH-013B` 连续治理：

1. 将唯一现代运行时与当前存档字段提升为 `player.soulCount`，P1/P2 分别持有。
2. `HeroSkillLearningState` 只保留心法树、主动技能和被动技能进度，不再拥有灵魂。
3. 存档升级到 V6；V1..V5 的 `skillLearning.soulCount` 只在迁移输入中出现，迁移后写入玩家直属字段。
4. 建立玩家级扣费合同；技能、炼丹炉、法宝等消费者只能对当前 owner 发起检查与扣减，不自行保存货币副本。
5. 禁止兼容层把直属字段镜像回 `skillLearning`；若阶段接线需要适配器，必须在第二个任务关闭前删除。

明确不做：

- 不改变灵魂初始值、既有消耗数值、掉落数值或技能规则。
- 不借此重构全部玩家状态或全部存档 schema。
- 不修改技能页面视觉和资源 bundle。

## 4. 测试方案

- 存档迁移：V1..V5 各自迁移到 V6，灵魂值不丢失；V6 重载稳定。
- 双玩家隔离：P1/P2 灵魂不同，任一玩家消费不影响另一玩家。
- 跨功能消费：技能、炼丹炉、法宝连续消费同一玩家字段，余额单调且存档重载一致。
- 负向门禁：当前 V6、运行时玩家状态和业务代码不得再声明或读取 `skillLearning.soulCount`。
- 回归：相关专项、全系统、build、structure、workflow、diff check 与正式功能页浏览器旅程通过。

## 5. 测试结果

`TASK-ARCH-013A` 已完成第一阶段治理：

- 当前 schema 升级为 V6，`PlayerFeatureSaveV6` 与 `LoadedPlayer1State` 直接声明 `soulCount`。
- `HeroSkillLearningState` 与 V6 `skillLearning` 不再声明灵魂；旧嵌套路径只保留在 V1..V5 legacy schema、迁移验证和负向测试。
- V1..V5→V6、V6 round-trip、P1/P2 不同余额、损坏/双源拒读专项通过。
- 技能、背包、宠物、工坊、法宝的现有保存入口均携带玩家直属余额，相关专项通过；统一消费服务、静态负向门禁和 940×590 跨功能旅程仍由 `TASK-ARCH-013B` 完成。

`TASK-ARCH-013B` 已完成第二阶段治理：

- 新增 `PlayerSoulSystem`，统一合法性、余额检查与扣减结果；技能、工坊强化/合成/分解/打造和法宝灵魂分支不再直接写余额。
- 余额不足、非法金额和失败事务保持余额/业务状态不变；消费者源码门禁禁止直接 `soulCount` 写入与 `skillLearning.soulCount` 回流。
- 正式旅程连续执行 P1 技能、工坊、法宝消费，再执行 P2 技能消费并重载，证明 P1/P2 隔离和同一 owner 余额连续。
- `npm run check:all`、`git diff --check` 与 940×590 单/双人正式功能页复验通过，console warning/error 为 0。

## 6. 关闭标准

- 当前 schema 和运行时唯一权威字段为 `player.soulCount`。
- V1..V5 旧档迁移值与原嵌套值一致，V6 不再生成嵌套灵魂。
- 技能、炼丹炉、法宝及已知灵魂消费者全部读取/扣减同一当前玩家字段。
- P1/P2 隔离、连续跨功能消费和保存重载均有自动回归。
- 搜索与负向测试能够阻止 `skillLearning.soulCount` 回流。
- 全部门禁和 940×590 正式旅程通过后，才可恢复 Stage 2-3。
