# PG-011 共享 UI 组件边界与迁移门禁缺失

状态：已确认，待治理。

来源：2026-07-25 用户在商城新增灵魂余额后再次发现黑框遮字，并追问灵魂、背包、关闭按钮等是否应正式组件化；用户确认组件化是需要多个 TASK 治理的大型工程。

## 1. 问题定义

项目已经出现可跨页面复用的灵魂余额、背包格子/分页、原生按钮状态与关闭生命周期，但这些能力尚未形成统一的组件边界、消费者矩阵和迁移门禁。部分页面复用共享 view，部分页面复制局部逻辑或重新制作视觉子件，导致“业务 owner 相同、视觉实现仍漂移”的反复返工。

这不是单个黑框或单个 helper 的问题，而是跨页面演进能力的结构性缺口：

- 新消费者无法明确判断应复用哪个组件、复用到哪一层、哪些原版布局必须保留。
- 数据 owner、Phaser 视图、页面 composition 和资源 provenance 容易混在同一个 page view。
- 复制已有组件的外观但没有复用其透明资源、字体度量、状态机和销毁合同，会产生看似相同、实际不同的实现。
- 反过来建立“万能按钮”“万能面板”又会抹平不同源 SWF 的按钮皮肤、矩阵、命中区和页面语义。
- 背包相关视图存在正式背包、炼丹炉材料格、商城商品/购买流和后续任务奖励等不同消费者，若一次性重构会跨越多个 owner 与正式旅程，无法在一个 Goal 内可靠验收。

## 2. 证据

- `FormalSoulBalanceView` 已作为技能页/炼丹炉共享余额投影使用；商城新增同款显示时，首轮仍从运行截图裁图，携带黑色舞台背景并遮挡文字，说明“已有组件”尚未转化为强制复用与资产 provenance 门禁。
- `PG-010` 的反馈记录显示灵魂显示先后出现标签侵入、黑底、字体回退和位置偏差；数据 owner 已统一并不能自动保证 UI 组件的一致性。
- `FormalInventoryPageView` 已具有四分类、分页、格子、selected 与真图标；炼丹炉、商城和后续任务页仍各自组合相近的格子/物品/奖励展示语义，尚无共享层与页面保留项矩阵。
- 设置、商城、炼丹炉、背包等页面均有关闭按钮与 Escape/返回/重复打开/销毁行为，但原生皮肤、矩阵和 host 语义并不完全相同；当前缺少“共享生命周期、保留页面皮肤”的明确合同。
- `PG-007` 能阻止现代可见层替代原版 UI，`PG-010` 能阻止灵魂数据 owner 回流，但两者都没有规定共享组件族如何建立、试点、分批迁移和防止页面重新复制。

## 3. 解决方案

建立 `LINE-SHARED-UI-COMPONENTS`，用一个 `Split` 父任务和六个独立 Goal/TASK 串行治理：

1. `TASK-ARCH-014A`：审计共享候选、消费者和重复 owner，冻结组件分层、命名、视觉保留项、资源 provenance、生命周期与迁移合同。
2. `TASK-ARCH-014B`：收敛 `SoulBalanceView` 组件族，迁移全部已知灵魂消费页面，并建立透明资源、嵌入字形、owner 与截图裁片负向门禁。
3. `TASK-ARCH-014C`：建立原生按钮/关闭生命周期组件族；只共享状态、命中、Escape、销毁和回调合同，各页面继续持有自己的原生皮肤与几何。
4. `TASK-ARCH-014D`：建立背包/物品展示基础组件族，包括 item cell、grid、分页、selected、tooltip/view-model 接缝；不把正式背包整页做成万能面板。
5. `TASK-ARCH-014E`：以正式背包页作为基础组件首个迁移试点，证明 431 身份、428 真图标、四分类、P1/P2 与 V6 行为无回归。
6. `TASK-ARCH-014F`：按审计矩阵迁移炼丹炉、商城、任务奖励等嵌入式消费者，完成跨页面旅程和整线关闭审计。

分层原则：

- system/domain owner 持有灵魂、inventory definition/transaction、按钮业务动作等事实。
- 共享 Phaser 组件只持有可销毁的视图对象、交互状态和只读投影，不复制业务状态。
- 页面 composition 持有原版 Symbol、坐标、矩阵、皮肤、命中区差异与页面专属流程。
- 资源 manifest/bundle 持有稳定 key、透明 alpha、来源 SWF/Symbol 和消费者 bundle；共享组件不得临时从截图或整页背景裁图。

明确不做：

- 不在一个 TASK 中重构所有 UI。
- 不建立统一现代外观的 `GenericButton`、`GenericPanel` 或万能背包页。
- 不改变灵魂数值、物品事务、存档 schema、任务奖励、页面可见布局或原版已确认行为。
- 不因名称相似而强制合并语义不同的格子、按钮或 tooltip。
- 不抢占当前 `LINE-PRE-STAGE-2-3-COMPLETION / GOAL-047`；新线和全部子任务先保持 Planned。

## 4. 测试方案

- 工作流门禁：`task-generation.md` 固定要求 `组件化合同` 六字段；`validate-workflow.mjs` 对共享 UI 组件化 task 做正/负样例校验。
- 静态边界：搜索页面私有的灵魂图标/数字渲染、重复按钮状态机、重复 item grid/page/selection 实现；按审计矩阵逐项归零或解释页面保留项。
- provenance：共享视觉子件必须具有来源 SWF/Symbol、透明 alpha、尺寸/矩阵和 bundle owner；负向样例必须拒绝截图裁片、舞台底色和整页背景切片。
- 确定性测试：组件创建、刷新、hover/pressed/disabled/selected、owner 切换、分页、空状态、销毁幂等与重复打开。
- 页面回归：每个迁移页面继续执行自己的业务专项、P1/P2、V6、返回/重开和正式入口回归。
- 视觉验收：940×590 下逐页面、逐状态对照原版基准；组件复用不能替代显示列表、并排/叠图和对象差异证据。
- 全局门禁：`check:structure`、专项、`test:systems`、`build`、`check:workflow`、`git diff --check` 以及正式跨页面旅程按各子任务范围通过。

## 5. 测试结果

当前仅完成治理登记和任务拆分，尚未开始代码迁移：

- `task-generation.md` 已新增共享 UI 组件化 task 门禁与固定 `组件化合同`。
- `validate-workflow.mjs` 已加入组件化合同的正样例、逐字段负样例和 task 定义检查。
- `LINE-SHARED-UI-COMPONENTS`、`TASK-ARCH-014 / 014A..F` 与 `GOAL-051..056` 已登记为 Planned，不改变当前唯一 Active 线/Goal。
- `npm run check:workflow` 通过：20 个未完成 task/定义、15 个 Goal、唯一推荐 `TASK-SLICE-155C`、唯一 Active `GOAL-047`；仅保留既有 `PlayerSlot` 命名 warning。`git diff --check` 无错误。
- 存量代码审计、组件实现、消费者迁移和运行验收仍待 `TASK-ARCH-014A..F` 执行；因此不能把问题状态提升为治理中或关闭。

## 6. 关闭标准

- 全部已知共享候选和消费者具有权威矩阵，组件、页面 composition、domain/system 与 bundle owner 边界无未解释重叠。
- 灵魂余额组件的全部已知消费者完成迁移，不再出现页面私有图标、字体、数字投影或截图裁片。
- 原生按钮/关闭组件至少覆盖代表性 overlay 与整页页面，同时保留各自原生皮肤、几何和 host 行为。
- 背包基础组件先通过正式背包试点，再完成全部声明的嵌入式消费者迁移；未迁移项必须有用户确认的排除理由。
- 新增或修改共享 UI 组件 task 会被工作流校验强制要求组件化合同，新增消费者会被静态/测试门禁阻止复制 owner。
- 每个迁移页面的业务、P1/P2、V6、逐状态视觉和返回/重开证据通过；最终跨页面正式旅程无 warning/error。
- `TASK-ARCH-014A..F` 全部归档且 `LINE-SHARED-UI-COMPONENTS` 覆盖台账无未解释缺口后，才能关闭 PG-011。

以下只能算部分缓解：

- 只修商城黑框，或只把现有 helper 政名为组件。
- 只建立共享组件，没有列出和迁移消费者。
- 只迁移一个页面，没有静态防回填与运行回归。
- 只统一按钮皮肤而没有生命周期，或用通用现代皮肤覆盖原生按钮。
- 只共享背包数据而没有收敛 view primitives，或把所有物品页面强行套入同一整页布局。

## 7. 适用触发与反馈记录

触发条件：

- 新增或修改灵魂余额、物品格子、背包分页、selected/tooltip、原生按钮、关闭按钮、Escape/返回或 feature UI host。
- 新增任何消费灵魂、展示 inventory item 或复用原版按钮状态的页面。
- 生成、拆分、实现、评审或关闭含“共享组件、组件化、背包组件、灵魂组件、通用按钮/关闭”的 task。
- 用户反馈黑框、遮字、字体/位置漂移、按钮行为不一致，或质疑为何没有直接复用已有组件。

效果检查：

- 对照消费者矩阵搜索新的页面私有 owner、重复 view/state helper 和资源裁片。
- 检查 task 是否同时具备 `UI 原生化合同` 与 `组件化合同`。
- 核对共享资产 provenance、透明 alpha、bundle owner 和页面原生几何保留项。
- 运行目标组件专项、页面业务回归和 940×590 逐状态验收。
