# PG-012 关卡结果协议按关卡漂移

状态：方案已落地，效果观察中。

来源：2026-07-26 用户试玩确认 Stage 1-1 再次不能按既定“Boss 死亡显光门，进入光门后按 W”完成关卡，并指出第一关与其他关卡的公共行为应统一。

## 1. 问题定义

项目曾没有面向全部关卡的共同生命周期/结果 owner。Stage 1-1 把 Boss arena、光门矩形、按上通关和结果 overlay 分散在 `LevelSystem`、`TestSceneBossArena`、`Stage11FlowSystem` 与 `TestSceneStage11FlowBridge`；Stage 1-2、1-3、2-1、2-2 又分别复制 Flow phase、2.5 秒判负、`tryCompleteStageXX()`、解锁目标和结果 bridge。首轮治理只收敛逻辑终态，遗漏了结果视图 owner，用户随后复验出 Stage 1-1 仍显示私有现代黑框。

重复实现已经产生可观察漂移：Stage 1-1 使用 X/Y 精确矩形，其他四关在 bridge 中使用光门 X 距离阈值；各关必须分别记住失败互斥、幂等通关、解锁和保存顺序。如果只修现有五关而不建立未来关卡的默认接入边界，每新增一关仍会复制一次完整 Flow，复杂度和遗漏风险会随关卡数量持续增长。

## 2. 证据

- `LevelSystem.tryClearArena()` 要求角色点同时进入光门 X/Y 精确矩形并按上，坐标直接取玩家 sprite 位置。
- `Stage12/13/21/22GameplayBridge` 各自以门中心 X 距离约束和玩家上键决定 `doorUsed`，没有与 Stage 1-1 共用空间语义。
- `Stage12/13/21/22FlowSystem` 分别复制 `tryCompleteStageXX()`、终态切换、失败倒计时和解锁写入；Stage 1-1 则由 `completeStage11()` 与 arena state 两级提交。
- 用户运行反馈与 M-014、VS-050 先前“已复现/已闭合”结论冲突，说明现有验证没有建立跨关防漂移门禁。

## 3. 解决方案

1. 建立可测试、可扩展、供全部后续关卡默认复用的生命周期/结果协议，统一终态、全员判负、出口可用、玩家交互、幂等通关、解锁目标和结果事件。
2. 普通光门 + 上键作为默认完成策略；特殊入口、特殊胜利条件或无门关卡只能通过有证据的窄策略/配置扩展，不得复制整套 Flow。
3. 关卡只提供显式配置与差异：出口区域/交互空间、解锁目标、专属 Boss/波次触发；Phaser bridge 只把玩家位置和输入转换为协议输入。
4. 迁移五个已完成关卡作为首批样本，优先恢复 Stage 1-1 单/双人光门 + 上键，再验证至少一个横向关卡。
5. 增加架构门禁，阻止后续 `Stage*FlowSystem` 重新定义同义终态、失败倒计时、解锁和结果提交。
6. 使用组合与纯逻辑 owner，不建立承载地形、怪物、镜头、UI、资源和存档的万能继承基类。
7. 本轮不修改怪物、波次、Boss、地图布局或 Stage 2-3 内容。
8. 结果展示同样属于公共协议：唯一 `LevelResultView` 消费原版 `GameWin/GameFail`，关卡只提供成绩与下一关/重试/返回回调；不得再新增逐关结果 bridge 或现代黑框。

## 4. 测试方案

- 纯系统测试覆盖门隐藏、门外按上、门内未按上、门内按上、双人任一玩家、重复触发、失败后不可通关、正确解锁目标和结果事件幂等。
- 五关集成测试证明不再存在同义 `tryCompleteStageXX()` 与关卡私有失败/解锁提交规则。
- 静态或架构测试阻止未来关卡绕过通用协议另建完整生命周期 owner；特殊策略必须显式登记并测试。
- 940×590 运行复验 Stage 1-1 单人、双人和一个横向关卡；检查结果页、当前槽保存、返回地图与重新进入。
- 运行 `npm run check:structure`、`npm run test:systems`、`npm run build`、`npm run check:workflow`、`git diff --check`。

## 5. 测试结果

`TASK-ARCH-015` 已落地纯逻辑 `LevelLifecycle` 和 Phaser `LevelLifecycleBridge`。五关 Flow 复用同一终态、2.5 秒全员判负、幂等通关与解锁 owner；普通出口统一以实际门/玩家 bounds 重叠和对应上键完成，特殊关卡通过可注入的窄完成策略扩展。Stage 2-2 的 Boss 内容子状态已从通用生命周期 phase 中拆出，保留为 `encounterPhase`。

`TASK-SLICE-161` 补齐首轮遗漏：从 `OtherMat1.swf` character 330/313 恢复原版 `GameWin/GameFail` 根视觉、三个按钮三态和四个动态成绩字段；五关全部改用唯一 `LevelResultView`，删除四个 `Stage*ResultBridge` 及 Stage 1-1 私有黑框创建代码。专项门禁阻止全屏现代 `Rectangle/Text` 与逐关结果 bridge 回填。940×590 运行验收确认成功页、失败页及按钮 hover 均为原版画面，console 无 warning/error。

由于关闭标准还要求至少一个未来新增关卡实际消费默认协议或窄策略，本问题保持“效果观察中”，不提前关闭。

## 6. 关闭标准

- 所有后续关卡有唯一默认的生命周期/结果协议和明确窄扩展点；五个已完成关卡完成首批迁移，关卡 bridge 不复制失败倒计时、终态、解锁和提交规则。
- Stage 1-1 单/双人均可稳定通过光门 + 对应上键通关，且门隐藏、门外、未按上、失败态不会误触发。
- 通关、解锁、保存和结果显示对重复输入保持幂等。
- 自动测试、构建、五关集成和规定的运行复验通过。
- 架构门禁已能阻止新增同义 Flow；至少一个后续关卡通过默认协议或有证据的窄策略接入且不新增私有结果 owner，才能从效果观察转为关闭。
