# PG-017 真值表不管用

状态：待治理（视觉真值方案已独立冻结；全面性校验器待独立对话讨论）。

来源：2026-08-19 用户在宠物战斗 HUD 复验中发现头像位置与内容错误，并指出现有产物虽标记为“真值”，却没有满足真值法要求；用户要求将其单独登记为“真值表不管用问题”，后续在其他对话讨论。

## 1. 问题定义

当前机器真值流程可以产出 Schema 合法、带源哈希、可重复生成、`status: verified`、`unresolved: []` 且测试通过的 JSON，但这些形式条件仍可能无法约束实现正确性。生成器、manifest、基准和消费者测试如果共享同一套错误假设，就会形成自洽闭环：表是稳定的，测试也是绿的，正式画面仍然错。

“真值表不管用”不是指 JSON 文件没有被读取，而是它未成为独立于实现的有效判据，典型表现包括：

- expected 集合由生成器自身硬编码，缺失对象不会被发现；
- 动态 MovieClip 只记录容器联合 bounds，没有执行目标帧或解析帧内子对象；
- `verified`、`displayListMatched`、`stateSetMatched`、`unresolved` 由生成器直接声明，而不是校验结果推导；
- 多状态基准复用同一张静态图，未证明原版真的进入对应状态；
- 实现与测试共同读取同一份错误 manifest，测试只能证明“一致”，不能证明“正确”；
- 源哈希与可重复生成被误当成语义正确性。

本问题与已归档 PG-005 不同：PG-005 治理的是六段证据链缺环却宣布闭合；PG-017 治理的是证据和真值产物形式上齐全、甚至被直接消费，但验证结构仍是自证循环，无法发现语义错误。与 PG-007 的关系也相同：原生化门禁存在，不代表真值本身有效。

## 2. 证据

宠物战斗 HUD 是首个明确反例：

- `tools/generate-pet-combat-hud-ground-truth.mjs` 硬编码状态、显示列表与坐标，只把 character 657 记录为 `headmc` 容器，并把约 `104.8 × 93.6` 的时间轴联合 bounds 当作头像显示尺寸。
- 原版 `ShowPetInfo.show()` 对 `headmc` 调用 `gotoAndStop(PetInfo.getPetChinaName())`；character 657 是 42 帧动态头像选择器。以“灵猴”为例，目标帧放置的是 character 619，其实际可见图形和注册偏移并不等于 657 的全时间轴联合 bounds。
- 现代 `Stage1PetCombatHudView.ts` 取得宠物身体 atlas 后，把它强制拉伸到真值表给出的 `104.8 × 93.6`，因此画面出现错误宠物图和错误定位；用户截图直接反证了“verified”结论。
- 生成器直接写入 `status: 'verified'`、`displayListMatched: true`、`stateSetMatched: true` 和 `unresolved: []`，这些字段不是独立校验的产物。
- `validate-ui-ground-truth.mjs` 主要验证 manifest 是否符合 Schema；Schema 合法不能发现漏掉动态帧 child 或选错 character。
- 现有 HUD 测试检查 truth id、PNG/资源存在和禁止现代 Graphics 等结构条件，没有用独立原版帧事实断言“灵猴必须是 character 619、具有对应 bounds/偏移”。
- 逐状态原版基准没有证明动态 `gotoAndStop` 的目标头像被实际执行；静态壳体截图与同源硬编码坐标相互印证，构成自我验证。

直接原因不是“实现没有读取真值”，而是生成阶段使用了过粗的提取单位，把逐状态动态显示语义压成静态容器几何；同时，生成产物是否全面尚无独立结论。

## 3. 解决方案

PG-017 只保存问题治理合同，不再承载逆向任务的详细拆解步骤：

- **生成逻辑治理方向**：真值生成只属于独立逆向任务下的 `视觉真值逆向` 子类型。任务模型和渐进读取见 `docs/workflow/reverse-engineering-task-protocol.md`；精细生成拆解作为独立输入方案保存在 `docs/reverse-engineering/plans/ground-truth-fine-grained-generation.md`。代码逆向沿用既有流程，不读取该方案或新增专用文档约束。
- **生成职责**：视觉真值逆向 task 负责声明范围内的 SWF/AS3 状态解析、目标帧/时间片、递归 child、动态显示变化、几何和产物生成；漏做应有提取属于视觉真值生成缺陷。
- **校验器职责**：全面性校验器只判断最终生成物是否全面，不监督生成器内部提取步骤；其边界和待决问题位于 `docs/workflow/ground-truth-completeness-validator.md`，方案留到独立对话讨论。
- **结果用语**：当前不另设 `correct/incorrect` 结果维度；产物在声明范围内被证明全面时，即把全面性证明作为真值成立结论。
- **调度边界**：2026-08-21 用户要求在原 193E 前实施该实例；已创建并激活 `TASK-SETTINGS-201`，其后串行 `TASK-SLICE-202` 正式消费。201 不修现代 HUD，202 不反向修改真值生成逻辑；两者都不批量降级既有 manifest，也不进入全面性校验器通用方案。
- **首个实例**：`TASK-SETTINGS-201` 以 character 657 为有界 `视觉真值逆向` task，在 `逆向方案：` 字段链接精细生成方案；只处理 `gotoAndStop` 的 35 个实际物种/形态 fixture 和 P1/P2 投影。`gotoAndPlay` 样本仍须另建后续视觉真值逆向 task。
- **存量审计**：最终按风险审计既有 `verified` manifest，优先动态时间轴、帧内嵌套、滤镜/mask、文本度量和多状态 UI，不因一个反例无差别否定所有静态真值。

## 4. 测试方案

- 执行精细生成方案的视觉真值逆向 task 必须通过该方案自己的验收；PG 只核对 task、方案、产物和验收记录是否形成可定位链路，不复制一份步骤清单。
- character 657 首个 task 完成后，核对具体宠物状态不再使用根容器联合 bounds 或身体 atlas 代替头像事实。
- 全面性校验器的输入、判定方法、结论枚举和专项测试留到独立对话冻结；PG 只核对它是否保持“判断产物全面”的职责。
- 生成与全面性校验均落地后，核对正式消费者：移除或篡改关键真值字段时运行测试必须失败；仅 import truth id 不算消费证明。

## 5. 测试结果

当前已确认宠物 HUD 是“形式验证通过、正式画面错误”的反例。精细生成拆解已冻结为只供视觉真值逆向使用的独立方案，代码/视觉真值子类型和校验器职责边界已建立。2026-08-24 `TASK-SETTINGS-201` 已完成首个实例：新真值以 35 项 corpus + AS3 映射独立声明 expected，以恢复 SWF XML/SVG/PNG 提取 actual，逐目标帧递归 child，生成 P1/P2 投影、负状态、逐 fixture baseline、独立全面性报告和 child/frame/matrix 变异自测；灵猴已从旧联合 bounds 纠正为 frame 5 / character 619。`TASK-SLICE-202` 已完成首个正式消费者：35 fixture/33 唯一终端 child 直接进入专属 bundle，frame/child/matrix/registration/visible-bounds 变异会改变或阻止投影，身体 atlas、联合 bounds 拉伸和硬编码头像定位均删除；九物种资源差异为 0，940×590 双人运行零 console。全面性校验器通用方案、至少两个后续任务与存量风险审计仍未完成，因此本问题仍为“待治理”，不能标为“已解决”。

## 6. 关闭标准

- 独立逆向任务的视觉真值子类型和精细生成方案被实际 task 消费，代码逆向保持原流程；真值流程明确区分可重复性、Schema 合法性、生成结果与全面性结论，`verified` 不再由生成器无条件自报。
- 宠物 HUD 的动态头像真值按实际状态帧递归生成，正式画面与原版状态一致，不再使用容器联合 bounds 或身体 atlas 代替头像状态。
- 独立对话完成全面性校验器方案并落地；校验器只裁决产物是否全面，不监督生成器内部提取步骤，也不另设 `correct/incorrect` 结果维度。
- 全面性校验器能发现动态 child 缺失、状态缺失、逐帧信息缺失和多状态静态基准复用，不再只验证 JSON 形状与文件存在。
- 至少两个后续真值任务完成“精细生成 + 全面性结论 + 正式消费者 + 运行差异”，其中至少一个包含动态时间轴。
- 对存量高风险 `verified` manifest 完成有界审计并记录保留、降级或修复结论。
- 用户或 reviewer 再次以正式画面反证真值时，流程能自动降级状态并阻止任务继续宣称闭合。

以下不算关闭：

- 只修宠物头像坐标或换一张正确图片。
- 只给 manifest 增加更多字段、哈希或截图，但动态状态仍以容器或联合 bounds 为提取单位。
- 只建立检查生成器内部步骤是否被调用的流程监督器，却没有判断最终产物是否全面。
- 只让实现读取更多真值字段，没有全面性结论。
- 因本次反例把所有旧真值一律判废，却没有按风险和语义逐项审计。

## 7. 适用触发与反馈记录

触发条件：

- 新增或修改 ground-truth generator、Schema、validator、baseline 生成器或正式 truth consumer。
- 目标含动态 MovieClip、`gotoAndStop`、嵌套时间轴、mask/filter、动态文本或多状态显示列表。
- manifest 标记 `verified/unresolved=[]`，但用户截图、原版运行或独立提取结果出现反证。
- 测试只检查 JSON 字面量、truth id、哈希、PNG 存在、Schema 合法或“实现与 manifest 一致”。

效果检查：

- 检查生成单位是否为声明状态下的目标帧/时间片和递归可见显示列表，而不是根容器或全时间轴联合 bounds。
- 对动态显示对象核对状态来源、真实目标帧、递归 child、矩阵、注册点、可见 bounds、时间语义和状态 fixture。
- 检查不支持的 SWF/AS3 语义是否显式进入 `unresolved`，以及 baseline 是否真正对应声明状态。
- 校验器相关变更只检查它是否判断产物全面；若转而监督生成器内部步骤、抽样范围小于产物声明范围却宣称全面，或重新引入单独的 `correct/incorrect` 结果维度，即判职责漂移。
