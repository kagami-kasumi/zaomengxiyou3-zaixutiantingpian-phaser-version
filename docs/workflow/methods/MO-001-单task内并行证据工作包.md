# MO-001 单 task 内并行证据工作包

状态：试验中。

提出者/来源：用户提出希望正式游戏 task 适配 subagent；2026-08-06 脚手架讨论。

负责人：每个适用任务的主 agent；协议级汇总由 workflow steward 负责。

最迟复核点：取得 3 个真实样本后，且不得晚于 2026-09-15。

## 1. 方法与假设

方法：保持唯一 Ready task、严格单线 `WIP=1` 和既有规模预算不变，在同一 task 内把互不依赖的证据调查或独立验证声明为并行工作包。主 agent 保留范围、事实裁决、实现整合、状态文档和最终验收所有权；subagent 默认只读。

假设：当任务同时需要 AS3 行为、恢复 SWF 视觉、现代消费者或独立验证中的至少两路调查时，并行只读工作包能减少主 agent 的串行等待和上下文切换，同时不增加证据误判、写入冲突、范围扩张或 compact。

本方法不扩大 task，不增加 Ready task，不允许多个 agent 各自宣布机制闭合，也不把 AS3 结构当现代架构模板。

## 2. 基线与指标

基线：由单一 agent 串行完成所有调查、实现、验证和文档收口；现有 Claude 专属角色定义虽可复用，但缺少跨客户端的工作包、归并和效果观测合同。

主指标：

- subagent 产出中被主 agent 直接用于决策或验证的独立发现数；
- 可避免的重复读取或重复搜索次数；
- 调查阶段的串行等待是否减少；可靠计时时记录墙钟时间，否则记录代理时间线和等待关系；
- 主 agent 为纠正、重做或补齐 subagent 结果产生的返工次数。

护栏指标：

- 共享工作区写入冲突数必须为 0；
- 因并行导致的 task 范围扩张、额外资料族或额外 compact 数必须为 0；
- 证据分级错误、遗漏实现影响未知项或错误闭合数必须为 0；
- task 的主工作包和独立验收批次仍不得超过既有预算。

## 3. 试验设计

- 取得至少 3 个真实样本，覆盖至少两类场景：逆向/视觉调查、实现前消费者调查、独立评审或脚手架维护。
- 每个样本在派发前声明问题、输入路径、允许操作、禁止范围、输出格式、写入 owner 和归并检查点。
- 默认只允许 subagent 只读；需要写入时必须分配互不重叠的文件集合，状态文档仍由主 agent 单写。
- 主 agent 在实现或关闭结论前核查来源、冲突和未知项，并记录实际采用与退回内容。
- task 本身不适合并行时不制造样本。

宠物进化族视觉真值 V2 试验使用个人内部 `$pet-family-reverse` 薄 Skill（`~/.codex/skills/pet-family-reverse/`）统一路由：Luna A 只读追踪 AS3 行为/共享调用链，Luna B 只读核对恢复 SWF owner/时间轴/几何，主 agent 归并后再以独立审查覆盖 expected/extracted、动态 child、基准与消费者。Skill 不替代仓库协议、任务调度、真值生成器或主 agent 的证据裁决。`TASK-SETTINGS-193E` 与 `TASK-SETTINGS-193G` 是计划中的两个真实视觉样本；未执行前不计入观测记录或采纳样本数。

停止条件：出现一次未被归并检查发现的错误闭合，或出现一次状态文档/同一文件写入冲突；出现两次明显协调返工高于直接串行工作的样本。

## 4. 采纳标准

- **采纳**：完成至少 3 个样本、覆盖至少两类场景；至少 2 个样本提供可直接采用的独立发现；所有护栏指标为 0；没有两次明显协调负收益。
- **修订**：方法有可复用收益，但工作包边界、角色路由、写入限制或指标需要调整。
- **停止**：命中停止条件，或 3 个样本中不足 2 个产生可用独立发现且协调成本没有下降证据。

单个成功样本只证明可行，不触发“已采纳”。
