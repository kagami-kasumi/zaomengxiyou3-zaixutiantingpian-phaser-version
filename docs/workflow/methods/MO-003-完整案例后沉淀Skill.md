## 1. 方法与假设

方法：不得在一个领域对象尚未完成“原版证据全集 → 现代实现 → 正式运行 → 反证复盘”前，把局部调查步骤固化为可复用 Skill。先完整完成一个代表案例，再从实际遗漏、返工、停止条件和验收证据中提炼 Skill；随后必须用第二个不同案例验证可复用性。

假设：完整案例优先能避免把视觉定位、Schema/哈希自检或结构门禁误当成完整逆向，减少后续批量复制不完整 Behavior、漏掉普通攻击/正式消费者和玩家可见运行的返工。

本方法不要求把超出零 compact 预算的逆向、实现和运行硬塞进一个 task；允许连续任务，但同一案例完成前不得切到其他家族，也不得提前宣告或强制使用 Skill。

## 2. 基线与指标

基线：当前先创建 `$pet-family-reverse` 薄 Skill，再按“视觉证据 → 动画实现”“公共 Runtime → 批量物种 Behavior → 最后迁消费者”横向拆分。204B 虽然 P1/P1B 门禁为 0，但正式游戏没有 `PetCombatRuntime` 消费者，`basicAttack` 也只有字符串事件，用户看不到宠物自主攻击。

主指标：

- 首个完整案例在 Skill 定稿前发现并关闭的遗漏阶段数；
- Skill 条目能否逐项定位到已完成案例的证据、实现和运行验收；
- 第二案例使用 Skill 时新增的重大遗漏、返工和补充步骤数；
- 从开始逆向到正式运行闭合期间是否发生跨家族切换或错误完成声明。

护栏指标：

- 不得以单个 gate、manifest `verified`、哈希、mock 或专项测试代替正式玩家可见运行；
- 首个案例完成前 Skill 强制消费者数必须为 0；
- 未知项不得因 Skill 已写而被补成原版事实；
- 连续任务仍遵守唯一 Ready、WIP=1、最多 2 工作包/2 验收批次和零 compact 预算。

## 4. 采纳标准

- **采纳**：猴系完整闭合；Skill 每个稳定步骤均可追到实际产物；第二家族没有重大遗漏或错误闭合，新增步骤只属于明确物种差异。
- **修订**：完整案例方法有效，但家族粒度、任务边界、验收顺序或 Skill 路由仍需调整。
- **停止**：完整案例成本没有带来可复用信息，或第二家族仍出现被 Skill 隐藏的重大遗漏/错误完成。
