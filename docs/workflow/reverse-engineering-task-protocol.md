# 独立逆向任务协议

本文把逆向工作建模为一种一等任务模型，并通过子类型做渐进式披露。逆向任务仍服从唯一 `Active` 功能线、唯一 `Ready`、任务看板和独立 task definition；它不是 PG 的一个段落，也不是实现任务中的临时步骤。

## 1. 任务模型与子类型

逆向任务是有 task id、状态、规模预算、输入、输出、完成定义和验收的可调度执行单元。新建或重新拆分的逆向任务必须声明：

```md
任务模型：
- 逆向任务

逆向子类型：
- 代码逆向 / 视觉真值逆向
```

当前只定义两个子类型：

- **代码逆向**：追踪 AS3、共享调用链、状态机、数值、时序和行为合同。现有做法暂未发现系统性问题，不新增专用方案文档约束，也不要求执行时读取本文；执行当前 task definition 与 `docs/workflow/reverse-engineering-protocol.md` 即可。
- **视觉真值逆向**：从恢复 SWF、时间轴、显示列表、帧、矩阵、注册点和运行状态生成机器真值。只有该子类型必须通过 `逆向方案：` 显式链接独立方案。

真值生成不是所有逆向任务的通用要求；只有目标涉及 UI、HUD、菜单、按钮、动画视觉或空间视觉，并需要产生 ground-truth manifest/baseline 时，才选择 `视觉真值逆向`。

现有 `TASK-SETTINGS-*` 编号继续作为兼容 ID，不批量迁移。`任务模型/逆向子类型` 是读取语义，ID 本身不再承担“猜测这是哪类逆向”的职责。

## 2. 渐进式读取顺序

所有逆向任务先执行：

1. 按正式游戏 task 规则检查 `execution-queue.md`、唯一 `Active` 功能线、唯一 `Ready` 和当前 task definition。
2. 读取 `docs/workflow/reverse-engineering-protocol.md`，取得六段证据链、证据分级和通用关闭门禁。
3. 只读取当前 task definition 列出的目标源资料、消费者和事实文档。

随后按 `逆向子类型` 分流：

- **代码逆向**：直接按当前 task 的待证明问题读取局部/共享 AS3 与必要消费者；不读取 `docs/reverse-engineering/plans/`、真值精细生成方案或 PG-017。
- **视觉真值逆向**：再读取当前 task 在 `逆向方案：` 中唯一链接的 `docs/reverse-engineering/plans/*.md`，以及方案明确要求的恢复 SWF、ground-truth 规范和视觉来源；不得扫描其他方案。

`PG-*` 只有在当前任务明确承担问题治理，或收尾问题审计语义命中时才读取。普通代码逆向和视觉真值逆向都不把 PG 当作任务手册。

## 3. Task definition 合同

所有逆向任务除通用 task 字段外，必须包含：

- `任务模型：逆向任务`；
- `逆向子类型：代码逆向/视觉真值逆向`；
- 待证明的可观察问题；
- 本 task 的有限范围、入口和源资料族；
- 输出产物、未知项、反证条件与验收；
- 明确禁止进入的现代实现和相邻资料族。

只有 `视觉真值逆向` 额外要求：

- 唯一 `逆向方案：docs/reverse-engineering/plans/*.md`；
- 状态/fixture、目标 Symbol/MovieClip/character 和视觉来源；
- 方案要求的 manifest、baseline、显示列表或逐帧产物路径。

推荐定义片段：

```md
任务模型：
- 逆向任务

逆向子类型：
- 代码逆向

逆向方案：
- 不适用
```

```md
任务模型：
- 逆向任务

逆向子类型：
- 视觉真值逆向

逆向方案：
- `docs/reverse-engineering/plans/<visual-truth-plan>.md`
```

视觉方案只定义可复用拆解方法；task definition 仍须把它实例化为有边界的范围、入口、状态/fixture、源资料族和产物，不能只写“按方案执行”。

## 4. 迁移与拆分

- 旧代码逆向 task 沿用已有 task definition 和通用逆向协议，不要求为历史上已经正常工作的代码逆向补建方案文档。
- 旧视觉/真值 task 可以继续留在看板；轮到执行或重新拆分时，补 `任务模型：逆向任务`、`逆向子类型：视觉真值逆向` 和唯一视觉方案，再开始读取视觉源资料。
- 代码逆向过程中首次发现必须生成视觉机器真值时，拆成同线 `视觉真值逆向` task，不在代码逆向 task 中顺带加载视觉方案。
- 视觉真值方案要求的新资料族、状态族或运行旅程超出 task 声明时，继续拆成同线视觉真值逆向 task。
- 逆向任务不修改现代 `src/`。需要实现时生成或激活同线后续 `TASK-ARCH/TASK-SLICE`。

## 5. 完成与交接

代码逆向按通用逆向协议交付证据矩阵、共享调用链、行为合同、未知和反证；不因没有视觉真值方案而降级。

视觉真值逆向还必须交付当前视觉方案要求的实例化产物及方案验收结果。两类任务完成时都要更新 `mechanics-index.md`、当前线覆盖台账和 task 状态，并让后续任务直接链接稳定产物，而不是读取 PG 恢复执行上下文。

完成一个逆向 task 只关闭该工作单元，不自动关闭功能线、PG 或现代实现切片。
