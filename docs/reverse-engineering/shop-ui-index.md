## 待证明的可观察问题

1. 五分类、九卡、分页、数量、确认、P1/P2、余额、充值和返回分别由哪些原 Symbol、depth、坐标与按钮状态组成。

## 可观察行为合同

### 进入、分类与分页

- 进入后刷新 `AllEquipment`，默认 owner=P1、分类=全部、页=1。
- 单人隐藏 P2；双人显示 P2。owner selected 通过 `upState=overState` 保持。
- 分类点击把当前页重置为 1，清空九卡动态商品，再按注册顺序填入；空卡整体隐藏。
- 分类 selected 通过 `upState=downState` 保持；五分类的 over/down 图相同。
- 前/后页按钮始终可见且没有 disabled 图；边界点击只是不改变页码。

### 数量与确认

- 新卡数量为 1；上箭头在数量 100 时停止，因此箭头路径是 1..100；下箭头在 1 时停止。
- `txt_num` 只允许数字且 `maxLength=2`，手输路径可为 0..99；0 或空值点击购买不会打开确认框。该原版输入不对手输值做额外夹取。
- 数量大于 0 时购买按钮创建 character 624；文字为“你确定要购买 N 个 NAME 总共花费 TOTAL 灵魂”。
- 取消：发 `BUYCHANGLE`，清除卡片待购标记并移除弹窗，不改灵魂/库存。
- 灵魂不足：显示“灵魂不足！”，发 `BUYCHANGLE`，移除弹窗，不改灵魂/库存。
- 成功：先设置 `gc.needlh=折后单价×数量`，发 `BuySuccess`；商城扣当前 owner 灵魂、把目标卡商品写入当前 owner、数量回 1并刷新余额，提示“购买成功！”。
- 宝石/道具/宠物走 `putQhsInBackPack()` 按 `fillName` 堆叠且没有容量拒绝；时装每件重新创建实例、写 `fashionTime=curdate` 后进入 `szlist`。商城自身唯一事务拒绝态是数量≤0与灵魂不足。

### owner、返回与生命周期

- 切 P1/P2 后余额和商品图标 owner 同步到对应 `User`；双方灵魂/库存不串改。
- 返回发 `SelectOver` 并从父级移除页面；`isingameshop` 在 add/remove 间为 true。
- 进入入口会同时发 `ShowOtherScene`，商城页由 `GMain.mainSence` 持有，不是关卡内 overlay。

## 离线、支付与存档边界

- **交叉确认**：根原图保留“充值”“1人民币=1游币=100点券”和网络保存失败提示，但 `btn_cz` 在此版本只显示“单机版请用灵魂购买~”；购买判断与扣减只读取当前 `User.getLhValue()`。
- `PayMoneyVar` 虽被构造但不参与成功门禁、扣款或商品发放；没有可达支付、账户、点券或网络事务。
- **纠正旧检查点**：购买成功末尾调用 `MemoryClass.setStorage(saveId)`，但 `setStorage()` 只重建 `mystorage` 内存对象，参数未被消费，也不写文件。真正落盘由返回地图后显式 `MapMenu.saveGame()` → `MemoryClass.saveGame(saveId,true)` 完成。这与顶部“返回地图，手动点击保存游戏按钮”静态提示一致。
- 现代 V6/localStorage 不必复制“购买后只做内存快照”的 Flash 文件 API 细节，但 `TASK-SLICE-155B` 必须明确选择保存时机并用现有当前槽 owner；不得把原版事实写成“确认购买后已经落盘”。

## 现代映射与视觉例外

- 现代 owner：现有 V6 `player*.soulCount`、当前槽 inventory/fashion 数据和共享 `PlayerSoulSystem`；不得建立商城私有灵魂副本。
- 现代页面必须逐 child 消费 `map-service.shop` 深层资源；不能把 721 整页 PNG/SVG作为可交互页面。
- 2026-07-25 用户批准在商城右下角增加与技能页/炼丹炉一致的共享灵魂余额组件，供消费灵魂的页面复用。商城保留 character 721 原有 `txt_money`，新增组件只投影同一当前 owner `soulCount`，不建立第二货币 owner；徽记必须直接使用 character 250 / shape 236 的透明 `PatternID_236_2`，禁止从整页截图裁切或携带背景色。这是明确批准的现代可见例外。
- 除上述共享余额组件外，默认零新增可见现代覆盖层。当前没有用户批准替换停服静态文字，因此实现应保留原静态表现与原版点击离线提示，同时不接入任何在线能力。
- 若产品决定替换人民币/点券/网络提示，必须先取得用户批准并把替换文字列为现代视觉例外；本 task 不预先批准。
