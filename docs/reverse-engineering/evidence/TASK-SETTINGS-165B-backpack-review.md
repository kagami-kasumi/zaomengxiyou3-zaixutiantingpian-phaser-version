## `TASK-SLICE-165C` 精确实现合同

1. 保持 304 舞台裁切、246 根坐标、关闭/翻页/分类原按钮与原命中区；允许的
   现代可见例外为零。
2. `InventoryGridProjection` 只读投影 5×5、50×51、step 61×60 的 25 格；
   `InventoryItemCell` 只读 identity/icon/quantity/instance/empty/selected，二者
   不持有或修改 inventory。
3. 实现上表全部 304 动态 child。战斗场景入口通过只读 presentation snapshot
   提供即时 HP/MP 等运行值；地图入口使用保存成长与 `EquipmentSystem` 有效属性
   回退。不得新增第二套角色/库存 owner。
4. 原版 nickname 在当前现代存档无独立字段；165C 以英雄名作显式现代映射，
   若以后出现权威 nickname owner 再替换，不把当前映射写成原版事实。
5. 角色容器优先复用现有英雄 body/equipment 视觉族或 origin runtime snapshot，
   不读取新 UI 源包；若实现时证明缺少必要角色视觉族，按拆分触发停止并补证。
6. 删除右侧现代详情、owner/message 文字和选中 tint；选择后在格内显示 610/358
   原生操作层。不支持的专属用途维持相应原生 disabled 控件，并由宿主提供非替代
   视觉的安全反馈，不能伪造效果。
7. 分类、页码、P1/P2、穿脱、动作提交、重入和销毁均重建/清理全部动态 child、
   弹层和监听，禁止叠字、串 owner 或幽灵对象。
8. 验收至少覆盖四分类、首/中/末页、空格/数量1/数量>1/实例、选择和弹层、
   六槽穿脱、拒绝态、P1/P2、战斗即时值/地图回退、关闭返回/再入/V6 重载；
   以确定性测试和 940×590 同尺寸对象差异共同裁决。
