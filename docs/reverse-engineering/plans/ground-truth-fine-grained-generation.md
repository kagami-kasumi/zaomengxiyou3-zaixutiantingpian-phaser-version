# 原版机器真值精细生成方案

方案状态：已冻结，尚未实施。

适用任务模型：`逆向任务`。

适用逆向子类型：`视觉真值逆向`。

来源问题：`PG-017 真值表不管用`。PG 只保留问题与治理合同；本文件只由 `视觉真值逆向` task 显式引用，代码逆向不得加载。

## 1. 目标

把 UI、HUD、菜单、按钮、动画和空间视觉真值从“根容器/全时间轴联合几何”细化为玩家实际状态下的可见事实。方案只负责真值生成，不讨论真值产物全面性校验器。

正式提取单位为：

`状态 fixture × 根 Symbol/MovieClip × 目标帧或时间片 × 该时刻的递归可见显示列表`

## 2. 任务输入

引用本方案的逆向任务必须实例化以下输入：

- 原版版本、舞台和业务入口；
- 目标根 Symbol/MovieClip/character；
- AS3 状态调用链和允许读取的源资料族；
- P1/P2、业务数据和状态 fixture 的有限集合；
- 恢复 SWF、必要的 FFDec/XML/SVG/PNG 交叉来源和当前事实文档；
- 本 task 的产物路径、规模预算和拆分触发。

缺少上述实例化时，任务不得只写“按本方案执行”后进入提取。

## 3. 拆解步骤

1. **冻结声明范围**：在提取前固定原版版本、入口、舞台、根 Symbol/MovieClip、P1/P2、业务输入、状态集合和状态 fixture。不得根据现代实现已经用到的对象反向缩小范围。
2. **解析状态来源**：从 AS3 调用链、帧标签、原始数据目录或运行入口确定状态如何进入。`gotoAndStop` 解析到实际目标帧；`gotoAndPlay` 解析起始帧、后续帧序列、持帧/时序、循环或停止条件；`addChild/addChildAt/removeChild` 等动态显示操作进入对应 fixture 的结果。
3. **选择准确时间点**：静态状态提取目标帧的完整显示树；播放动画按玩家可见时间序列逐帧提取。不得用根容器所有帧的联合 bounds 代替某一状态、某一帧或某段动画。
4. **递归展开显示列表**：从目标根对象沿当前帧实际放置关系递归到可见 child，记录 character id、实例名、depth、父子关系、帧号/标签、放置/替换/移除关系。嵌套 MovieClip 继续按其当前帧展开，不能停在动态容器壳体。
5. **提取显示语义**：逐对象记录 local matrix、注册点、局部 bounds、颜色变换、alpha、blend mode、mask、filter、裁切、按钮态、文本度量和资源引用；不适用项显式标记，不得静默略过。
6. **计算逐状态几何**：只使用当前状态实际显示树逐层组合矩阵，生成 local、parent、stage 坐标与最终可见 bounds。派生值保留推导方法和源 locator。
7. **序列化动态变化**：对播放动画记录每帧显示列表差异、可见范围和时间语义；对数据驱动 UI 记录 fixture 值与动态对象的对应关系。多个状态视觉确实相同可以共享资源，但仍保留各自状态入口和显示结构。
8. **显式处理未知能力**：遇到尚不能解释的 SWF tag、时间轴行为、AS3 动态值、滤镜、遮罩、文本或外部资源时，写入 `unresolved` 并停止把该范围声明为 `verified`；不得因 Schema 合法、源哈希存在或任务可重复运行而忽略未知。
9. **生成规范化产物**：manifest 中的状态、对象、矩阵、边界、时序和基准引用来自上述逐状态结果。`expected` 不使用与源提取脱离的手写对象清单，也不与 `extracted` 机械复制后自报匹配。
10. **生成逐状态基准**：基准记录状态 fixture、目标帧/时间片、舞台和裁切；禁止用静态壳体图冒充已经执行动态头像、按钮、分页或播放动画的状态基准。

## 4. 输出产物

引用本方案的任务按自身范围生成：

- 状态 fixture 与源入口映射；
- 目标帧/时间序列和递归显示列表事实；
- 逐对象身份、父子/depth、矩阵、注册点、局部/舞台/可见 bounds 与显示语义；
- 动态显示列表和时间语义；
- 规范化 ground-truth manifest；
- 可追溯逐状态 baseline；
- 来源 hash/locator、推导方法、`unresolved` 和证据矩阵引用；
- 后续消费者所需的稳定路径，不把本方案或 PG 当作运行时数据源。

## 5. 方案验收

- `gotoAndStop` 样本只生成目标状态帧的递归显示树，不使用根容器联合 bounds。
- `gotoAndPlay` 样本生成任务声明时间段内的帧序列、显示列表变化、时序与终止/循环语义。
- 嵌套 MovieClip、mask/filter、动态文本和 `addChild/removeChild` 在适用 fixture 中有显式产物；不支持项进入 `unresolved` 并阻止 `verified`。
- 每个 baseline 的状态 fixture、目标帧/时间片和裁切可定位；动态状态不复用未注入状态的静态壳体图。
- 两次生成得到稳定产物，Schema、来源哈希和可重复性分别报告；这些形式结果不自行充当全面性结论。

## 6. 范围与拆分

- 不要求预先把全部恢复 SWF 无差别拆成全部帧和位图；简单静态对象保持较小产物。
- 动态 MovieClip、嵌套时间轴和动态显示列表必须按任务声明状态展开到能表达玩家可见结果的粒度。
- 首个建议实例是 character 657 宠物头像，覆盖宠物名到目标帧、帧内 character、递归 child、注册偏移、可见 bounds 和 P1/P2 投影。
- `gotoAndPlay` 动画作为后续独立逆向任务；不得把完整 Flash 虚拟机研发和 character 657 首个样本塞进同一个 task。
- 本方案不研发或裁决全面性校验器；校验器讨论入口为 `docs/workflow/ground-truth-completeness-validator.md`。
