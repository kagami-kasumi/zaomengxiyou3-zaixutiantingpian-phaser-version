## 验收环境

- 原版基准：恢复语料库中的商城 940×590 原始截图 `original-root-940x590.png`。
- 现代实现：Phaser 940×590，内置浏览器在正式存档入口进入天庭商城。

## 现代边界

- 商品、顺序、价格、Stage 3 后八折与 `zylhys` 例外均消费既有闭合证据。
- 购买统一进入现代背包容量与堆叠上限 owner；失败时不扣灵魂。
- 成功购买立即写入当前 V6 活跃槽位，是获批离线边界内的现代可靠性选择，不宣称为原 Flash 保存时机。
- 本次实际为 2 个主工作包、2 个独立验收批次。首次 compact 发生在实现、资源、浏览器逐状态证据和专项确定性测试全部完成之后；compact 后只进行台账、治理反馈和既有检查收尾，没有读取新资料族、派生新资源或新增实现。

## 2026-07-25 用户反馈补充

- 用户批准在商城右下角增加与技能页/炼丹炉一致的共享灵魂余额组件；character 721 原有底栏余额继续保留。
- 首轮错误地从运行截图裁出徽记，连同黑色舞台背景一起生成 86×78 PNG，用户复验发现黑框再次遮字；该实现结论作废。
- 最终实现直接提取 character 250 / shape 236 的 `PatternID_236_2`：82×82 RGBA 原 PNG，使用原矩阵坐标 `(732,504.95)`，没有背景色或遮罩；生成脚本和专项测试锁定透明源、尺寸与 RGBA 类型。
- 组件继续复用嵌入 `FZCuYuan-M03` 数字轮廓，直接读取当前 P1/P2 owner 的同一 `soulCount`；购买与换人重绘会同步刷新。
- 修复后 940×590 运行观察确认：单人 owner 显示 `6900`，徽记外部透出页面背景且没有矩形边界；新增组件不遮挡分类、商品卡、分页、返回或原底栏。
- `npm run test:shop`、`npm run test:asset-bundles` 与 `npm run build` 通过；这是用户批准的现代可见例外，不改写原版显示列表事实。
