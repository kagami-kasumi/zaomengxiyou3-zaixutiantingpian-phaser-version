# TASK-SETTINGS-215 behavior evidence notes

This is a bounded, static first hand evidence set for incoming `pnum` producers in the `[172845].swf` legacy extraction. It covers Hero, Pet, BaseBullet attack id de duplication, the required Role overrides, continuous poison/fire display paths, shield short circuits and overflow, `dzjj` MP transfer, and the absence of `addHpLose` callers. It does not claim that these cases have been native or SWF visually tested.

The important correction is that Hero damage dispatches `SetHHp`, but `BaseRoleProperies.setHHP` performs the actual clamp: negative HP becomes `0`, and HP above `SHHP` becomes `SHHP` (BaseRoleProperies 815-839). The pnum producer still receives the incoming damage argument, so displayed damage and actual HP delta can differ on lethal hits.

Shield handling is ordered. `MAGIC_UMBRELLA_DEFEND`/`DEFEND2` consume and return before `tjgl_Shield` (BaseHero 802-813). A full `tjgl_Shield` hit produces no reduceHp pnum, but an explicit caller such as `getHurtByPig8` can still display one. With exactly one tjgl shield of 5 and incoming 20, `reducetjglShieldDef` removes the shield and recursively applies residual 15 (BaseAddEffect 2734-2755), giving the bounded fixture’s pnum `[15]` and HP delta `-15`.

`dzjj` consumes three times the residual lethal damage from MP after HP reaches zero (BaseHero 863-916). `reduceMp` dispatches `SetMMp` and queues the `mp_` glyph (BaseHero 386-393; CureHpQueue 60-69); it does not call `addHeroHurtMc`, so the MP transfer is not an extra `pnum` producer.

`getHurtByPig8` is an explicit duplicate path: it calls `reduceHp(param1)` and then `addHeroHurtMc(param1)` (BaseHero 1197-1201). In single/local execution `reduceHp` itself also calls `addHeroHurtMc`, giving two pnum instances; a remote room receiver does not execute the local producer branch and therefore has only the explicit call. A full tjgl shield therefore still yields one explicit pig8 pnum. Poison and Monster6008Fire have the same single-player double-display shape because they combine `reduceHp` with an explicit Hero pnum call.

Role3 has a display-only override: while GXP, `addHeroHurtMc` divides the pnum argument by two (Role3 1999-2008), while its `reduceHp` separately applies the GXP damage multiplier (Role3 1201-1222). Fixtures must keep displayed value and actual damage as separate assertions.

`BaseBullet` prevents repeated application to the same target by checking and then pushing `target.beAttackIdArray` with `getAttackId()` (BaseBullet 301-325). This is attack-id/target de duplication, not CureHpQueue semantic de duplication. `CureHpQueue.addHpLose` exists and writes `pnum`, but an exact full-package `rg -n -F 'addHpLose' .../scripts` finds only its definition, so it is not an active producer fixture.

AIR evidence supplied by the main line confirms `ANumber.aNumImage(-12)` displays `012`; this is a numeric glyph conversion and carries no negative-sign glyph contract. Remote synchronization fixtures use explicit sequences only: `100=>90=>90=>100=>90` yields pnum `[10,10]`; there is no sequence-number de duplication. Arbitrary network reordering remains outside this bounded contract. The JSON key is `fixtures` and every fixture includes source locators and contains checks.

The queue stage cases target `CureHpQueue.addHpLose` specifically: stage 98 rejects the `pnum` entry, while another stage permits it (CureHpQueue 71-84). Remote pet decrease/same/before-start branches mirror the Hero listener gates, and `hurtOther` returns immediately when `gc.isInHost()` (BaseMutiLevelListenering 1212-1219). IceThron and FireThron are included as the same AS3 source family environment producers: unprotected collision calls `reduceHp` with randomized 15±5 and 45±5 respectively, while `isYourFather` rejects the call (IceThron 68-77; FireThron 67-76). These are behavior entries only; no graphics re-reverse-engineering is implied.
